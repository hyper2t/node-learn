## L4.1 老师"待处理"汇总（约 0.5–1 天，不改表）

**要解决**：老师有多个学生时，只能一个个点进关系看有没有要点评的证据。

**后端** `GET /v1/review-queue`（仅教师角色）
- 在该老师所有**进行中**的关系里，一次性查：
  - 等点评的证据：状态为 `submitted` 或 `revised`；
  - 学生申请确认完成的目标：`completionRequestedAt` 不为空。
- 返回 `{ items: ReviewQueueItem[], counts: { evidence, goals } }`，按**等待时间从久到新**排序（先交的先处理）。
  - `ReviewQueueItem = { kind: 'evidence' | 'goal', relationId, student: PersonRef, id, title, since, version? }`
- 查询次数固定：关系 1 次 + 证据 1 次 + 目标 1 次 + 人员信息 1 次（和 L2 的 `nextActionsFor` 同一做法），上限 200 条。

**前端**
- 新页面 `/(app)/review`：列表，每项显示学生头像和名字、证据标题（重交的标"第 N 版"）或"申请确认目标"、已等待多久（超过 3 天标黄）。点进去直接到证据详情页或关系页。
- 老师首页"需要关注"区加一张卡片："N 份证据待点评 · M 个目标待确认"，点击进入汇总页；数量为 0 时不显示。
- 不新增底部标签页（和问答一样）。

**测试**：只返回自己的、只返回进行中关系的、排序正确、学生调用返回 403。

## L4.2 结课总结（约 1 天）

**要解决**：关系结束后什么都没留下，学生拿不到可以回顾或展示的东西。

**生成**
- 关系变为 `ended` 时，自动生成一份**快照**，写入新表 `relation_summaries`（行 ID = 关系 ID，一段关系一份，重试不会重复）：
  - 起止日期、持续周数；
  - 目标：已完成的（含完成日期）、放弃的、未完成的；
  - 数字：完成任务数、提交证据数、收到反馈数、修改次数（沿用学习证明口径）；
  - 里程碑列表（每条指向真实的目标和证据）；
  - 结束方和结束理由；
  - **老师结课寄语**（可选，见下）。
- 快照在结束那一刻生成，之后关系里的数据被清理（比如对方注销）也不影响总结。
- 已经结束的老关系：第一次打开总结页时补生成。

**老师结课寄语**
- 结束后 **14 天内**老师可以写或修改一段寄语（≤1000 字），写好后通知学生。超过 14 天只读。

**查看和导出**
- 新页面 `/(app)/relations/[id]/summary`：只有双方能看。已结束的关系页顶部横幅加"查看结课总结"按钮。
- **导出**：页面提供"复制为文本"（Markdown 格式）和"打印 / 存为 PDF"（web 用浏览器打印，原生端用系统分享发送文本）。不引入 PDF 生成库。
- 不提供公开分享链接（隐私，尤其是未成年学生）。

**表 `relation_summaries`**：relationId、studentId、teacherId、startedAt、endedAt、endedBy、endReason、goalsJson(text)、countsJson、milestonesJson(text)、closingNote(text)、closingNoteAt，加 createdAt/updatedAt；索引 studentId、teacherId。

**测试**：结束时生成、重复结束不重复生成、寄语 14 天限制、只有老师能写寄语、非成员 403。

## L4.3 学生评价老师（约 1–1.5 天）

**要解决**：教师资料页的"评价数"目前是拿点评次数凑的，学生选老师时没有来自其他学生的真实参考。

**规则（默认值，需确认）**
1. **谁能评**：只有学生能评老师（不做老师评学生）。
2. **何时能评**：关系结束后；或者关系进行满 **30 天**后也可以评（长期关系不必等结束）。
3. **每段关系一条**：可以在 **30 天内**修改，之后锁定。
4. **内容**：1–5 星必填，文字选填（≤800 字）。另有 3 个可选标签（"讲解清楚""反馈及时""有耐心"），**不设负面标签**。
5. **老师回复**：老师可以公开回复一次（≤500 字），可修改。
6. **公开范围**：显示在教师资料页。**评价数满 3 条才显示平均分**，不足 3 条只显示条数和内容。
7. **未成年学生**：只计入星级，**文字不公开**（只有老师本人能看到），署名显示为"一位学生"。
8. **成年学生署名**：默认显示名字；评价时可以勾选"匿名显示"（老师本人仍能看到是谁）。
9. **治理**：老师或任何人都可以举报一条评价，走现有举报流程；管理员处理动作新增"移除评价"（沿用问答的 `remove_content`）。老师**不能**自己删评价。
10. **排序**：教师搜索的 `most_reviewed` 改为按真实评价数排序。不做按平均分排序。

**后端**
- 新表 `teacher_reviews`：行 ID = 关系 ID（保证一段关系一条），relationId、teacherId、studentId、rating(integer)、body(text)、tags(varchar[] 数组)、anonymous(boolean)、studentIsMinor(boolean)、reply(text)、replyAt、editableUntil、removedAt/removedBy，加 createdAt/updatedAt；索引 teacher_created、student。
- 接口：
  - `PUT /v1/relations/:id/review`：学生写或改（受第 2、3 条限制）；
  - `POST /v1/relations/:id/review/reply`：老师回复；
  - `GET /v1/teachers/:id/reviews?cursor`：公开列表（已登录可见，按第 6–8 条处理可见性）；
  - 教师资料 `signals` 增加 `reviewCount`、`avgRating`（不足 3 条时为 null）。
- `teacher_profiles` 增加 `reviewCount`、`ratingSum` 两列作为计数，写评价时更新；每日清理任务顺带重算一次，纠正并发造成的偏差。
- 通知：`review.received`（给老师）、`review.replied`（给学生）。

**前端**
- 结课总结页和关系页（满足条件时）显示"评价老师"卡片：星级、标签、文字、匿名勾选。
- 教师资料页新增"学生评价"区：条数、平均分（≥3 条）、列表（分页）、老师回复。
- 老师在自己的关系页能看到评价，并能回复。

**测试**：学生以外的人不能评、时间条件、30 天锁定、一段关系一条、未成年学生文字不公开、不足 3 条平均分为 null、计数正确、被移除的评价不计入。
